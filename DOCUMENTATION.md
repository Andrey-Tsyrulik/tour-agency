=== БЕЗОПАСНОСТЬ ===
- Пароли: bcrypt, cost factor 10
- Токены: JWT, expire 7d, передаются в Authorization: Bearer <token>
- Middleware auth.js верифицирует токен на каждом защищённом маршруте
- Middleware role.js блокирует доступ при недостаточной роли (403)

=== ОСОБЕННОСТИ РЕАЛИЗАЦИИ ===

Эффекты: limb darkening, pole darkening, атмосферное свечение, солнечный блик, спекулярный отблеск. ~170 drawImage-вызовов на кадр. requestAnimationFrame, 0.0004 рад/кадр.

4. Дизайн страницы авторизации: светло-голубой градиент (#C8E8F8→#87C8EE) имитирует дневное небо, SVG-облака с blur-фильтрами и анимацией дрейфа, солнечное свечение в углу.

## Аннотация

Данная работа посвящена разработке полнофункционального веб-приложения для туристического агентства **Tour Agency**. Приложение реализует весь жизненный цикл туристического сервиса: от просмотра каталога туров до оформления бронирования и оплаты. В системе предусмотрены три роли пользователей с разграничением доступа — клиент, агент и администратор.

---

## 1. Введение

### 1.1 Актуальность темы

В условиях цифровизации туристической отрасли возрастает потребность в автоматизированных системах управления туристическими продуктами и взаимоотношениями с клиентами. Традиционные подходы к работе с клиентами (телефонные звонки, личные визиты, бумажный документооборот) уступают место онлайн-платформам, обеспечивающим круглосуточный доступ к услугам и мгновенное оформление заказов.

Разработанная система «Tour Agency» является ответом на данный запрос: она предоставляет пользователям удобный интерфейс для самостоятельного выбора, бронирования и оплаты туров, а персоналу агентства — инструменты для управления каталогом, контроля бронирований и администрирования клиентской базы.

### 1.2 Цели и задачи

**Цель работы**: разработать полнофункциональное веб-приложение для туристического агентства с ролевой моделью доступа.

**Задачи**:
- Проектирование реляционной базы данных для хранения информации о турах, пользователях, бронированиях и платежах
- Разработка серверного REST API на Node.js/Express с авторизацией на основе JWT-токенов
- Разработка клиентского интерфейса на React с адаптивным дизайном
- Реализация ролевой модели доступа (пользователь, агент, администратор)
- Реализация многошагового процесса бронирования с выбором транспорта, дат и формы оплаты
- Реализация модуля управления пользователями с возможностью создания агентов администратором
- Обеспечение безопасности хранения паролей (хэширование bcrypt) и передачи данных (JWT)

### 1.3 Объект и предмет исследования

**Объект**: процессы автоматизации туристического агентства.

**Предмет**: веб-приложение для управления туристическими продуктами и бронированиями.

## 2. Анализ предметной области

### 2.1 Описание бизнес-процессов

Туристическое агентство выполняет следующие основные функции:
- Формирование и публикация каталога туристических продуктов
- Приём и обработка заявок на бронирование
- Работа с клиентской базой
- Приём платежей
- Информационная поддержка клиентов

**Диаграмма бизнес-процессов (словесная)**:
```
Клиент → Выбор тура → Бронирование → Оплата → Подтверждение агентом → Выполнение тура
Агент  → Управление каталогом туров → Обработка бронирований → Работа с клиентами
Администратор → Управление персоналом → Администрирование системы → Контроль финансов
```

### 2.2 Аналоги и конкуренты

| Система | Достоинства | Недостатки |
|---|---|---|
| Aviasales | Агрегатор, большая база | Нет ролей персонала, нет CRM |
| TurPoisk | Поиск туров, фильтры | Нет личного кабинета агента |
| Собственная CRM-система | Полный контроль | Высокая стоимость разработки |
| **Tour Agency** (наша система) | Полный цикл, роли, адаптивный UI | Учебный проект |

### 2.3 Требования к системе

**Функциональные требования**:
1. Регистрация и авторизация пользователей
2. Просмотр каталога туров с фильтрацией и поиском
3. Пошаговое оформление бронирования
4. Обработка платежей (карта, СБП, наличные)
5. Личный кабинет пользователя
6. Панель агента (управление турами и бронированиями)
7. Панель администратора (управление всей системой)
8. История просмотров и бронирований

**Нефункциональные требования**:
- Время ответа API: не более 300 мс
- Безопасность: хэширование паролей bcrypt, JWT-токены
- Адаптивность: поддержка мобильных устройств
- Доступность: веб-интерфейс, работающий в современных браузерах

│           React SPA (Single Page Application)               │

                          │ HTTP/REST API (axios)

### 4.2 REST API — Описание эндпоинтов

### 4.3 Ролевая модель

В системе реализована трёхуровневая ролевая модель:

| Роль | Создание | Возможности |
|---|---|---|
| `user` | Самостоятельная регистрация | Просмотр туров, бронирование, оплата, личный кабинет |
| `agent` | Только администратором | Всё что user + управление турами и бронированиями |
| `admin` | Предустановлен в системе | Всё что agent + управление пользователями |

**Важно**: при самостоятельной регистрации пользователь всегда получает роль `user`. Роль `agent` назначается только администратором через панель управления. Существует единственный предустановленный администратор: `admin@touragency.com`.

### 4.4 Авторизация и безопасность

#### Хэширование паролей
```javascript
// Регистрация — хэширование перед сохранением
const hashPassword = bcrypt.hashSync(password, 10);

// Вход — сравнение с хэшем
const valid = bcrypt.compareSync(password, user.password);
```

#### JWT-токены
```javascript
// Создание токена (срок действия 7 дней)
const token = jwt.sign(
  { id: user.id, role: user.role, name: user.name },
  process.env.JWT_SECRET,
  { expiresIn: '7d' }
);

// Проверка в middleware
const decoded = jwt.verify(token, JWT_SECRET);
req.user = decoded;
```

#### Middleware проверки роли
```javascript
// Проверка авторизации
const authMiddleware = (req, res, next) => {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ message: 'Требуется авторизация' });
  req.user = jwt.verify(token, JWT_SECRET);
  next();
};

// Проверка роли
const requireRole = (...roles) => (req, res, next) => {
  if (!roles.includes(req.user.role))
    return res.status(403).json({ message: 'Доступ запрещён' });
  next();
};
```

### 4.5 Процесс бронирования тура (многошаговая форма)

Бронирование реализовано в виде мастера из 5 шагов:

**Шаг 0 — Просмотр тура**: отображение детальной информации, рейтинга, описания, цены.

**Шаг 1 — Выбор города отправления**: 17 городов России, выбор количества гостей (1–20 человек).

**Шаг 2 — Выбор транспорта и класса**:
- Виды транспорта: самолёт (+5000 ₽), поезд (+2000 ₽), автобус (+800 ₽), автомобиль (без доплаты)
- Классы: эконом (базовая цена), бизнес (×1.8 к цене)
- Предварительный расчёт стоимости в реальном времени

**Шаг 3 — Выбор дат**: собственный компонент календаря с блокировкой прошедших дат и валидацией диапазона (дата отъезда > дата прибытия).

**Шаг 4 — Оплата**:
- Банковская карта: валидация номера (16 цифр), срока действия (ММ/ГГ), CVV, имени держателя
- СБП: эмуляция подтверждения
- Наличные: оплата при заезде

**Шаг 5 — Подтверждение**: сводка бронирования, сохранение в базе данных.

**Формула расчёта стоимости**:
```
totalPrice = (tourPrice + transportAddition × guests) × classMultiplier × guests
```

### 5.2 Тестирование пользовательских сценариев

1. Регистрация → Каталог туров → Фильтрация → Выбор тура → Бронирование → Оплата → Подтверждение

1. Вход как администратор → Панель администратора → Пользователи → Создать → роль «Агент»

В ходе выполнения работы было спроектировано и реализовано веб-приложение «Tour Agency» — система управления туристическим агентством, включающая:

2. **Реляционную базу данных** PostgreSQL с нормализованной схемой из пяти таблиц, обеспечивающей хранение информации о пользователях, турах, бронированиях, платежах и истории просмотров.

5. **Комплексный процесс бронирования** — пятишаговый мастер с выбором транспорта, дат, оплатой и валидацией данных.
